원 계획서: `LabFit KR 해커톤 계획서 (1).pdf`. 이 문서는 구현하면서 바뀐 결정과 이후 계획만 적는다.

## 3. 계획만: 교수 응답 가능성(바쁨) 평가

> 구현하지 않음. 아이디어와 설계 메모만 남긴다.

### 문제
지도교수 후보를 찾아도, 일이 많은 교수는 R&E 제안 메일에 답하지 않거나 거절하는 경우가 많다. 학생은 연락 순서를 정할 근거가 없어 답이 없을 가능성이 높은 교수부터 연락하고 시간을 잃는다.

### 무엇을 보여줄 것인가
"이 교수는 바쁘다"는 단정이 아니라, **연락 우선순위를 정하는 참고 신호**로 보여준다. 카드에 "응답 가능성 참고" 영역을 두고 근거가 된 수치를 그대로 노출한다. 점수 하나로 합치지 않는다.

### 후보 신호 (공개 데이터로 계산 가능한 것)

| 신호 | 데이터 | 해석 | 주의 |
|---|---|---|---|
| 최근 논문 생산량 | OpenAlex 최근 2년 논문 수 | 매우 많으면 대형 연구실 → 교수 본인 시간이 적을 수 있음 | 분야마다 기준이 크게 다름 → 같은 분야 안 백분위로만 표시 |
| 연구실 규모 | 최근 논문의 공저자 수, 같은 소속 공저자 수 | 대형 연구실은 학생 지도를 박사과정이 맡는 경우가 많음 (오히려 장점일 수 있음) | 해석이 양방향 |
| 동시 수행 과제 | NTIS 연구책임자 과제 수 | 과제가 많으면 바쁨 | NTIS 공개 API 범위 확인 필요 (원 계획서의 미확인 항목) |
| 직책 | 학과·기관 페이지 (학장, 센터장 등) | 보직이 있으면 응답이 늦을 가능성 | 웹 검색 필요, 정확도 낮음 |
| 고등학생 지도 이력 | 웹 검색: "R&E", "영재학교", "과학고" + 교수명 | 이력이 있으면 응답 가능성 높음 | 가장 유용하지만 데이터가 드묾 |
| 실제 응답 기록 | 학생들이 남기는 "답장 받음/거절/무응답" 기록 | 가장 직접적인 신호 | 표본이 쌓여야 의미가 생김. 교수 개인에 대한 평가로 번질 위험 → 공개 범위·익명화 정책 필요 |

### 설계 원칙
- 신호마다 근거(숫자·출처 링크)를 붙인다. 근거 없는 추정은 표시하지 않는다 (기존 근거 원칙과 같음).
- "바쁨" 같은 부정적 라벨을 공개적으로 붙이지 않는다. "연락 팁"으로 표현한다 (예: "대형 연구실 — 박사과정 연구원에게 함께 연락하면 답을 받을 가능성이 높아질 수 있음").
- 순위(0.5·T + 0.5·M)에는 섞지 않는다. 필터나 정렬 옵션으로만 쓴다.
- 실제 응답 기록은 개인정보·평판 문제가 있어 가장 나중에, 정책을 정한 뒤에만 한다.

### 검증 방법 (구현한다면)
R&E를 해본 선배들의 실제 연락 기록(누구에게 보냈고 답이 왔는지)을 모아, 위 신호들이 응답 여부와 상관이 있는지 먼저 본다. 상관이 없으면 기능을 만들지 않는다.
